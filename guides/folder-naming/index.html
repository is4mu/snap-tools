案件フォルダとファイル命名ルールの決め方

結論

探す時間が長い人ほど、フォルダ階層とファイル名の「型」がありません。個人または少人数なら、深い階層より浅い共通型の方が守れます。20分で初版を決め、あとは案件名だけ差し替えます。特定のクラウド製品の操作には依存しません。

フォルダ階層の最小セット

案件ごとに次だけで始めます。

YYYY_案件名/
  00_admin/      … 見積もり、契約メモ、請求
  10_input/      … 支給素材、参考
  20_work/       … 作業中
  30_share/      … 先方に出すもの
  40_delivery/   … 最終納品の控え

「share」と「delivery」を分けるのが要点です。共有中の草案と、最終版の控えが混ざると、どれが正本か分からなくなります。

ファイル名に入れる要素

優先順は次です。

  1. 日付（YYYYMMDD）
  2. 内容（何のファイルか）
  3. 版（v01 / v02 / final）

例: 20260806_採用LP_トップ_v03.fig
スペースや「最終の最終」は避け、版番号か日付のどちらかで新旧を判断できるようにします。

やってはいけない命名（失敗例）

  • 新しいフォルダ、untitled、コピー
  • 最終、本当の最終、最終2 の連鎖
  • 先方共有用と作業用を同じ名前で上書き

「最終」という言葉は感情であって版情報ではありません。v最終と書くなら、それ以上の更新が無い日付をフォルダの 40_delivery/ に残します。

決め方の手順

  1. 上の最小セットを1案件に適用する
  2. ファイル名の要素順（日付→内容→版）をメモする
  3. 先方共有は必ず 30_share/ 経由にする
  4. 2週間運用し、使っていないフォルダを削る
  5. チームに広げるなら 少人数チーム向けテンプレ へ

コピー用テンプレ

YYYY_案件名/
  00_admin/
  10_input/
  20_work/
  30_share/
  40_delivery/

命名: YYYYMMDD_内容_v01
共有は 30_share のみ。最終控えは 40_delivery。

FAQ

日付はフォルダとファイルどちらに入れる？

案件フォルダは開始月（YYYY_案件名）、ファイルは更新日を推奨します。両方に長い日付を重ねると読みにくくなります。

版番号と日付、どちらを優先？

同じ日に何度も出すなら版番号、日をまたぐなら日付が分かりやすいです。混在させるなら「日付＋版」の順で固定してください。

クライアント共有用と作業用は分ける？

分けてください。権限と誤送付のリスクが違います。

過去案件の移行はどう進める？

一気に整理しないでください。新規案件から新ルールを適用し、過去分は触ったときだけ移す方が続きます。
