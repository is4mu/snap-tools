## 結論

納品メールの目的は「成果物を受け取ってもらうこと」、請求メールの目的は「支払い手続きに進んでもらうこと」です。1通に詰め込むと、どちらも後回しにされがちです。分けて送る習慣をつけると、経理担当への転送も楽になり、自分の催促も減ります。

## いつ分けるか

基本は**納品と請求を別メール**にします。相手から同時指定がある場合のみ例外とし、そのときも件名と本文で「納品」「請求」のブロックを分けます。

送る順番の目安:

1. 納品メール（成果物の場所・確認方法）  
2. 相手の受領確認または無連絡期間のあと  
3. 請求メール（請求書・支払期限）  

同日に送る場合でも、件名を変えて2通に分けると、検索と転送がしやすくなります。

## 納品メールの型

入れる要素は4つです。

1. 何を納品したか（案件名・版）  
2. どこにあるか（リンク・添付・パス）  
3. 確認してほしいこと（1〜2点に絞る）  
4. 問い合わせ先  

```
件名: 【納品】採用LPデザイン 最終データ

〇〇様

お世話になっております。△△です。
採用LPデザインの最終データを納品いたします。

【納品物】
・Figmaデータ（リンク）
・書き出し画像一式（添付）

【ご確認】
表示崩れ・リンク切れがないかご確認ください。
修正があれば〇月〇日までにご連絡をお願いします。

ご不明点があれば本メールへご返信ください。
```

## 請求メールの型

請求書のフォーマットや制度の解説はここでは扱いません。メールでは「何の請求か」「いつまでに」「どこへ」をはっきり書きます。

```
件名: 【ご請求】採用LPデザイン 制作費

〇〇様

お世話になっております。△△です。
先日納品の採用LPデザインについて、ご請求いたします。

【請求内容】採用LPデザイン制作費
【金額】〇〇円（税別）
【お支払期限】〇月〇日
【請求書】別添のPDFをご確認ください

お振込先は請求書に記載しております。
ご経理で不明点があればお知らせください。
```

金額の根拠や範囲は [見積もり文の書き方](/guides/estimate-letter/) と揃えておきます。進捗の途中報告は [進捗連絡テンプレート](/guides/progress-templates/) の型を使い、請求メールと混ぜない方がよいです。

## 送る前のチェック手順

1. 納品物が開ける状態か（権限・パスワード・添付サイズ）  
2. 宛先が納品用と請求用で同じか、経理別アドレスか確認  
3. 件名に案件名と「納品」「請求」が入っているか  
4. 請求金額が見積もりと一致しているか  
5. 納品メールと請求メールを別スレッドにしたか  

詳しい項目は [納品前チェックリスト](/guides/delivery-checklist/) と [納品チェックツール](/tools/delivery-checklist/) を併用してください。

## 失敗例

納品リンクと請求書を1通に入れ、確認も支払いも後回しになるパターンです。分け、請求は納品から1〜2営業日空けると催促が減ります。

## FAQ

### 納品物と請求書は同じメールでよいか？

相手の指定がなければ分けます。同時がよいと言われた場合のみ、本文内で「納品」「請求」の見出しを分けてください。

### 件名に何を入れる？

【納品】または【ご請求】＋案件名が検索しやすい型です。日付や版数があると、再納品・再請求のときも区別できます。

### 再請求・催促は別テンプレが必要？

別メールにします。件名は【再送：ご請求】や【お支払期限のご確認】のように、初回と区別します。文面は短く、事実と期限だけを書きます。

### チャット納品でもメールは送る？

記録用に納品メールを送るチームは多いです。請求は経理の都合でメールが無難です。
